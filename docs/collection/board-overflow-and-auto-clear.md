# Board paging and automatic Ready collection

Shared boards (above 760px, without `phone=1`) measure each list's available height and show as many fixed-height rows as fit. Both columns reserve space for a `+ X more` indicator. Each column independently pages every seven seconds in its existing sort order and wraps to its first group. Newly Ready transitions reset only the Ready column to its newest-first group. Resize recalculates capacity. Below 761px and on the QR link (`phone=1`), all active rows remain visible in the scrollable personal-phone queue.

Migration `202610090002_ready_auto_clear.sql` adds workspace setting `ready_auto_clear_seconds`. NULL is Off; supported values are 300, 600, 900, 1200 and 1800 seconds. Existing businesses and new businesses default to 600 seconds. Changing a duration applies to the original Ready timestamp, including currently Ready orders; overdue orders may collect on the next worker run. Off preserves them until staff collect them.

A private SECURITY DEFINER worker runs through Supabase `pg_cron` every 30 seconds, using database time and row locks with SKIP LOCKED. It updates status to Collected and reuses the normal timestamp and realtime invalidation triggers. No order rows are deleted. Returning an order to Preparing removes it from expiry eligibility; marking it Ready again restarts ready_at through the existing trigger. Manual collection excludes it from future runs. The worker can tidy expired workspaces without granting any additional member access. Anonymous and authenticated clients cannot invoke it.

Apply the pending migrations in order later using the normal database release workflow, including `202610090001_automatic_order_numbers.sql` if not already applied. Do not run tests against hosted Supabase. The migration enables `pg_cron` and installs the named `popbia-auto-collect-ready` job. On the hosted project, verify that job is active and inspect its runs for success. Expiry normally happens within 30 seconds after the selected duration, and catches up after database downtime. No browser or Edge Function deployment, keys or external scheduler are needed for expiry.

Local verification: `SUPABASE_TEST_WORKDIR=<disposable CLI project> npm run test:collection` exercises real scheduled execution, independent paging, QR/mobile views, realtime and the existing security/entitlement suite. `SUPABASE_TEST_DB_CONTAINER=<local container> npm run test:entitlement-migration` checks existing-data/default preservation in an isolated temporary database (the scheduling clause is tested by the browser suite in the main local database).
